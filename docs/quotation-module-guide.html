1 · நோக்கம் — What this module is for

வாடிக்கையாளருக்கு ஒரு விலைப் புள்ளி (quotation / மதிப்பீடு) தயாரித்து, விலை நிர்ணயம் செய்து, சேமித்து, பின்னர் திறந்து பார்க்க / திருத்த / நீக்கப் பயன்படும் திரை. இது Qt desktop client-இல் இருந்த "Quotation Entry" திரையின் React port.

1.1 வணிக ரீதியாக இது என்ன செய்கிறது

  • ஒரு customer-ஐத் தேர்ந்தெடுத்து அவரது master-இல் இருந்து விலைநிலை (price level), பகுதி, salesman, மற்றும் freight / loading / unloading / promotion பொருந்துமா என்பதை எடுத்துக்கொள்கிறது.
  • பல item வரிகள் — ஒவ்வொன்றுக்கும் அளவு, unit, விலை, நான்கு வகை discount, GST / cess.
  • பல additional charge வரிகள் — freight, loading, cash discount, மற்றவை — ஒவ்வொன்றும் item வரிகளின் மேல் பரவுகிறது.
  • ஆவணம் முழுவதற்கும் taxable, CGST/SGST/IGST, cess, round-off, bill மற்றும் இரண்டு புள்ளிவிவரங்கள் (customer saving, company margin).
  • POST /quotations/create மூலம் சேமிப்பு (ஒரே route create + update இரண்டுக்கும்).

1.2 இந்த port-இன் மைய வடிவமைப்பு முடிவு

4.4 toBaseFactorKnown — ஒரு persist ஆகாத column-இன் விளைவு

sqi_to_base_factor DB-இல் சேமிக்கப்படுவதில்லை. Load-இல் அது சேமித்த அளவுகளில் இருந்து பின்னோக்கிக் கணக்கிடப்படுகிறது: 

netQty = caseQty × factor + billQty × (lengthQty || 1)
     ⟹ factor = (netQty − billQty × (lengthQty || 1)) / caseQty
பொறி

caseQty === 0 ஆக இருந்தால் வகுக்க ஒன்றுமில்லை — factor 1 ஆக load ஆகும். அது placeholder, உண்மையான factor அல்ல. அந்த 1-க்கு எதிராக Case Qty type செய்தால் caseQty × 1 — சரியான பணத்தின் ஒரு பகுதி மட்டுமே quote ஆகும். அதனால் toBaseFactorKnown: caseQty !== 0, மற்றும் Case Qty முதன்முதலில் தொடும்போது recoverBaseFactor() item lookup-இல் இருந்து உண்மையான factor-ஐ மட்டும் எடுக்கிறது.

5.1 இரண்டு cross-cutting விதிகள்

Slice-இன் reducer-ஐ ஒரு wrapper சுற்றுகிறது. இது ஒவ்வொரு case-இலும் திரும்பத் திரும்ப எழுதாமல் இரண்டு விதிகளை ஒரே இடத்தில் வைக்கிறது: 

export function quotationReducer(state, action) {
  const next = quotationSlice.reducer(state, action);
  if (state === undefined || next === state || NON_EDIT_ACTIONS.has(action.type)) {
    return next;                       // ← store init, மாற்றமில்லை, அல்லது edit அல்ல
  }
  if (next.isDirty && next.pricing === "live") {
    return next;                       // ← ஏற்கனவே அப்படித்தான், தேவையற்ற copy வேண்டாம்
  }
  return { ...next, isDirty: true, pricing: "live" };
}

மற்ற slice-களின் actions மற்றும் RTK Query-இன் ஒவ்வொரு action-ம் இதன் வழியாகச் செல்கின்றன — ஆனால் அவை state-ஐ மாற்றாததால் (next === state) draft-ஐ dirty ஆக்க முடியாது.
